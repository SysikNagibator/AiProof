# Internationalization

i18n is first-class. Every user-visible string — TUI, CLI help and output, gate block
messages, receipt HTML, doctor hints, errors — goes through a catalog. There are no
concatenated sentences: templates are full sentences with `{named}` placeholders.

Draft catalogs declare `reviewed = false` in their `[meta]` header and fall back to English
per missing key. The About/Settings screens show an unobtrusive "(machine-translated)" note
for any non-reviewed catalog (the current menu-cycle badge is derived from
`i18n.is_reviewed()`).

Run the completeness report:

```sh
python tools/gen_catalog_report.py          # human table
python tools/gen_catalog_report.py --strict # non-zero if en/ru incomplete (CI gate)
```

build; en/ru do.

## Lookup and fallback

`src/aiproof/i18n/__init__.py`:

* `t(key, lang, **kwargs)` — dotted-key lookup, then English fallback.
* `plural(key, n, lang)` — ICU-style plural helper with correct CLDR categories:
  one/few/many for ru/uk, other for zh/ja/ko, and de/es/fr/pt/tr rules.
* `available()`, `is_reviewed(code)`, `KNOWN_LANGS`.

## Detection order

1. `--lang <code>` global flag (forces the language for one run).
2. `AIPROOF_LANG` environment variable.
3. Saved setting in `~/.aiproof/config.toml` (written by `aiproof lang <code>`).
4. OS locale (`locale`; on Windows `GetUserDefaultUILanguage`).
5. Fallback `en`.

Per-key fallback chain: requested language → English.

## Agent-facing vs human-facing language

Gate block messages are read by the **agent**, not the human. The setting
`agent_message_language` (`auto|en|<code>`, default `en`) controls their language: agents
follow English most reliably. The human-facing UI, CLI and receipt follow the UI language.
Keep the two independent.

## Claim packs are separate

Phrase tables for claim extraction live under `src/aiproof/claims/lang/` and are **not** the
UI catalogs. They are described in `docs/CLAIMS.md` and tested independently.

## Contributing a translation

1. Copy `src/aiproof/i18n/catalogs/en.toml` to a temp file.
2. Translate every value; keep every `{placeholder}` exactly as in English.
3. Save as `<code>.toml`, set `[meta] reviewed = false` (or `true` once a native speaker
   reviews it), and add the code to `KNOWN_LANGS` in `src/aiproof/i18n/__init__.py`.
4. Run `python tools/gen_catalog_report.py` — placeholders must match (`0` mismatched).
5. Run the tests: `pytest tests/test_i18n.py`.

The test suite enforces: (1) every English key exists in Russian; (2) placeholder parity;
(3) Russian plural forms; (4) that all catalogs parse. Add a snapshot/width test when you add
a language whose script differs in width.
